# 交通信号灯控制器

依据 [第7章·行为级建模.ppt](<D:/在校生活 - 本科/上课学习/26秋/Verilog/以前课件/第7章.行为级建模.ppt>) 的 7.9 节“举例3——交通信号灯控制器”。

## 课件规定的接口与行为

核心模块 `sig_control` 保留课件的端口名称、宽度和方向：

| 端口 | 方向 / 位宽 | 含义 |
| --- | --- | --- |
| clock | 输入 / 1 位 | 状态在时钟上升沿更新 |
| clear | 输入 / 1 位 | 高电平同步复位，返回 S0 |
| X | 输入 / 1 位 | 乡村公路有车等待为 1，无车为 0 |
| hwy | 输出 / 2 位 | 主干道灯色编码 |
| cntry | 输出 / 2 位 | 乡村公路灯色编码 |

两路输出统一编码为红灯 00、黄灯 01、绿灯 10；不是每种颜色各占一位。

| 状态 | 主路 hwy | 支路 cntry | 转移条件 |
| --- | --- | --- | --- |
| S0 | 绿 | 红 | X=0 保持；X=1 转 S1 |
| S1 | 黄 | 红 | 保持 Y2RDELAY 个周期后转 S2 |
| S2 | 红 | 红 | 保持 R2GDELAY 个周期后转 S3 |
| S3 | 红 | 绿 | X=1 保持；X=0 转 S4 |
| S4 | 红 | 黄 | 保持 Y2RDELAY 个周期后转 S0 |

课件给出 Y2RDELAY=3、R2GDELAY=2，单位是 clock 周期，没有指定时钟频率、实际秒数、Basys3 引脚、拨码开关或 LED 分配，也没有要求倒计时数码管。

S3 没有固定最长绿灯时间；只要 X=1 就保持支路绿灯。进入 S1 后，即使 X 提前变为 0，仍依次经过 S1、S2、S3，再按 X=0 进入 S4。S4 结束直接返回 S0，与课件状态图一致。

## 可综合实现

课件用 `repeat (...) @(posedge clock)` 描述延时。本实现用 `delay_count` 寄存器计数，在进入 S1、S2、S4 时清零，完整保持指定周期数后再转移。组合逻辑使用 `always @*` 并完整赋值。

这是按课件状态图和延时参数意图实现的可综合电路，不逐事件复刻原示例跨多个 always 块的仿真调度。延时参数应为正整数。非法状态输出两路红灯，并在下一时钟沿返回 S0。

## 本版补充的 Basys3 约定

工程顶层为 `traffic_control`，内部实例化 `sig_control`。

- 板上 clock 为 100 MHz，CLOCK_HZ 默认 100,000,000。
- 核心 Y2RDELAY 覆盖为 3 × CLOCK_HZ，R2GDELAY 覆盖为 2 × CLOCK_HZ，即黄灯 3 秒、S2 全红 2 秒。这些秒数是本版便于观察的选择，不是课件指定的实时时间。
- 全部寄存器使用同一个 100 MHz 时钟，不产生新的低速时钟。
- X 经两级寄存器同步后进入核心。clear 仍为高电平同步复位。
- 上电后先把 SW0 置 1 复位，再置 0 运行。

| 顶层信号 | 板上器件 | 引脚 |
| --- | --- | --- |
| clock | 100 MHz 晶振 | W5 |
| clear | SW0 | V17 |
| X | SW1 | V16 |
| hwy[1] | LD1 | E19 |
| hwy[0] | LD0 | U16 |
| cntry[1] | LD3 | V19 |
| cntry[0] | LD2 | U19 |

XDC 使用 LVCMOS33 并声明 10 ns 输入时钟周期。物理引脚对照 [Digilent 官方 Basys3 XDC](https://github.com/Digilent/digilent-xdc/blob/master/Basys-3-Master.xdc)。

LED 显示的是二进制编码，不是独立的红、黄、绿实体灯：每组两盏灯全灭代表红灯，低位亮代表黄灯，高位亮代表绿灯。主路看 LD1～LD0，支路看 LD3～LD2。

## 功能仿真及验证

两份测试文件都只声明必要输入输出信号，不使用 exp、i、err 等辅助变量：

- `tb_sig_control`：测试核心默认 3/2 周期延时、五个状态、持续有车、请求中途撤销，以及每个状态下的同步复位；780 ns 结束。
- `tb_traffic_control`：工程默认仿真顶层。CLOCK_HZ 覆盖为 2，以加速观察板级流程，黄灯为 6 个时钟周期、S2 为 4 个周期；验证 X 同步、循环和复位；920 ns 结束。

输入仿真时钟周期均为 10 ns。Vivado 中运行 Run Behavioral Simulation 即可，默认仿真时长 1 us。要检查核心，在 Simulation Sources 中把 tb_sig_control 设为仿真顶层；综合顶层保持 traffic_control。

板级加速仿真的第一次完整状态序列如下：

| 时间 | 状态 | hwy | cntry |
| --- | --- | --- | --- |
| 5 ns | S0（复位） | 10 | 00 |
| 95 ns | S1 | 01 | 00 |
| 155 ns | S2 | 00 | 00 |
| 195 ns | S3 | 00 | 10 |
| 345 ns | S4 | 00 | 01 |
| 405 ns | S0 | 10 | 00 |

2026-09-23 使用 Vivado 2015.2 XSim 仿真并在测试文件之外核对 VCD：核心 161 个波形时间点、24 次状态转换通过；板级 183 个时间点、14 次状态转换通过。两路输出与预定状态及时间一致，没有在核对的时间点同时为绿灯。非时钟边沿的 clear 变化不会立即改变状态，下一上升沿才复位。

默认 100 MHz 参数的单模块综合与 XDC 检查通过：37 个触发器、0 个锁存器，综合过程报告 0 errors、0 critical warnings、0 warnings。旧版工具启动时的 Tcl Store 目录报错及 WebTalk 遥测报错未阻止检查完成。没有按真实秒数运行全周期仿真，也未执行布局布线、生成比特流或下载实验板。

## 上板观察

重新打开 traffic_control.xpr 加载新增文件。需要上板时再完成实现和比特流生成，通过 Hardware Manager 下载：

1. SW0=1 复位，主路编码 10、支路编码 00；SW0=0 开始运行。
2. SW1=0 时保持主路绿、支路红。
3. SW1=1 后，主路黄灯保持 3 秒，然后全红 2 秒，再变为主路红、支路绿。
4. 保持 SW1=1，支路继续绿灯；SW1=0 后支路黄灯保持 3 秒，再恢复主路绿、支路红。
5. 任意阶段 SW0=1，下一输入时钟上升沿返回初始状态。
